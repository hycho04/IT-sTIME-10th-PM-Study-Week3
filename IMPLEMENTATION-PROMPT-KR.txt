1. 작업 환경과 자료 확인
- 현재 폴더, 기존 코드, Git 상태, 원격 저장소와 작업 브랜치를 확인한다.
- 기존 프로젝트가 있으면 유지한다. 빈 프로젝트일 때만 React + Vite + TypeScript + Tailwind CSS로 초기 설정한다.
- 저장소 URL만으로 파일 수정 권한이나 GitHub 인증이 있다고 가정하지 않는다.
- 실제로 읽은 자료, 읽지 못한 자료, 누락된 자료를 짧게 보고한다.
- 추출 코드가 한 파일에 여러 화면을 포함해도 내가 미리 나눌 필요 없이 프레임명·화면 내용·구조를 기준으로 분리한다.
- 추출물이 CSS나 속성 정보만 담고 있다면 완성된 화면 코드로 취급하지 않는다. 해당 자료로 확인 가능한 구조와 스타일을 사용하고, 빠진 화면 구조나 에셋을 표시한다.
- 화면 ID ↔ 원본 프레임 ↔ 구성 요소 번호 ↔ Feature ID ↔ 출처의 매핑을 파일로 남긴다.
- 프레임 번호와 구성 요소 번호를 구별한다. 대응이 불확실하면 임의로 연결하지 않는다.
- 원본에 구성 요소 번호가 없으면 문서용 번호 01, 02…를 부여하고 ‘문서용 번호 · 화면 정의서 구성 순서’라고 표시한다. 원본 번호라고 설명하지 않는다.
- 접근할 수 없는 자료를 읽었다고 하거나, 없는 화면을 원본 디자인처럼 만들어 넣지 않는다.
- 필수 정보가 없으면 해당 부분만 질문하고 독립적으로 진행 가능한 작업은 계속한다.

2. 공통 문서 사이트
- 상단에 서비스 아이콘 또는 서비스명, ‘화면설계서와 기능명세서’, 버전, 프로젝트명을 표시한다.
- 상단 메뉴는 ‘전체 흐름 보기 / 문서 보기 / 시연하기’ 세 개로 구성한다.
- 문서 인쇄 버튼을 제공하고 인쇄할 때 탐색 버튼을 숨기며 본문과 명세가 잘리지 않게 한다.
- 흰색 카드, 밝은 회색 배경, 얇은 테두리, 둥근 모서리를 사용한다. 문서 탐색 강조색은 초록, 구성 요소 번호는 보라색을 기본으로 한다. 실제 서비스 디자인은 제공 자료를 따른다.
- 문서 본문은 가운데 정렬하고 넓은 화면에 좌우 여백을 둔다. 최대 너비는 약 1440~1540px 범위에서 조정한다.
- 작은 화면에서는 단일 열로 배치하고 페이지 전체에 가로 넘침이 생기지 않게 한다.

3. 전체 흐름 보기
- 화면별 카드를 목록으로 제공한다. 카드 내부는 다음 순서로 세로 배치한다.
  화면 ID·유형 → 화면명 → 작은 정적 화면 미리보기 → 화면 목적 → 다음 이동 경로 → ‘문서 보기’와 ‘시연하기’ 버튼.
- 미리보기는 원본 프레임 비율을 유지한다. 카드 안에서 클릭하거나 입력하는 기능은 제공하지 않는다.
- 데스크톱은 너비에 따라 3~4열, 태블릿은 2열, 모바일은 1열을 기본으로 한다.
- 문서 보기 버튼은 해당 화면 문서로, 시연하기 버튼은 해당 화면의 독립 데모로 진입한다.
- 원문 IA와 User Flow가 있을 때만 확인된 순서와 조건을 표시한다. 자료가 없으면 화면 목록과 명세서의 진입·종료 경로를 보여주고 임의로 흐름을 만들지 않는다.
- 없는 프레임은 ‘프레임 미제공’으로 표시한다.

4. 문서 보기 — 아래 순서를 그대로 따른다
한 화면의 문서를 페이지 전체의 세로 스크롤로 읽도록 만든다.

A. 화면 개요
- 이전 화면 / 화면명·화면 ID·유형 / 다음 화면을 표시한다.
- 화면 목적, 들어오는 곳, 나가는 곳, 서비스 Route, 문서 원본, Figma 자료 출처를 표시한다.
- 이전·다음은 문서 탐색 순서다. 실제 서비스 이동 흐름으로 오해되지 않게 한다.
- Figma 링크가 없고 추출 코드만 있으면 ‘Dev Mode 추출 코드 · 프레임 XX’처럼 실제 출처를 표시한다.

B. 화면 설명 | 구성 요소와 동작
- 화면 목적과 표시 정보를 읽기 쉬운 문장으로 제공한다.
- ‘주요 동작’과 ‘상태·예외 처리’를 카드로 보여준다.
- 기본·로딩·빈·오류·비활성 상태, 이동 조건, 반응형·접근성 요구는 원문에 있는 범위에서 표시한다.

C. Figma 화면과 번호별 구성 요소
- 넓은 화면에서는 왼쪽에 크게 읽을 수 있는 프레임, 오른쪽에 번호별 설명 목록을 둔다.
- 공간이 부족하면 프레임을 위에 크게 두고 설명 목록을 아래에 배치한다.
- 기본 배율은 실제 프레임 컨테이너 너비를 측정해 비율을 유지하며 최대한 맞춘다. 창 크기가 바뀌어도 화면 맞춤 배율을 갱신한다.
- 확대·축소 버튼, 배율 슬라이더, 현재 배율, ‘화면 맞춤’ 버튼을 제공한다. 기본 조절 범위는 25~160%이고 화면 맞춤에 더 작은 배율이 필요하면 이를 지원한다.
- 확대 시 프레임 영역 안에서 가로·세로로 이동할 수 있게 한다. 왼쪽 가장자리까지 접근 가능해야 하며 페이지 전체를 가로로 밀어내면 안 된다.
- 화면 맞춤 상태에서는 불필요한 내부 스크롤을 줄인다.
- 실제 구성 요소 위치에 보라색 테두리와 01, 02… 원형 번호를 표시한다.
- 각 번호·영역을 선택하면 같은 문서의 해당 설명으로 이동하고 선택 상태를 강조한다. 설명 목록 선택 시 해당 영역을 강조한다.
- 번호와 영역은 확대·축소해도 일치해야 한다. 요소의 실제 DOM 위치나 정확한 좌표를 기준으로 연결하고 일괄 추정 좌표로 잘못된 요소를 가리키지 않는다.
- 문서의 프레임은 설명 탐색용이다. 프레임 안 버튼을 눌러 데모 기능이 실행되거나 서비스 화면으로 이동하게 하지 않는다.
- 번호 버튼에 접근 가능한 이름과 키보드 포커스를 제공한다.

D. 기능명세
- 프레임과 구성 요소 아래에 해당 화면과 연결된 Feature ID별 카드를 세로로 나열한다.
- 기능 ID, 기능명, 목적, 유형·중요도, 연결 화면, 원문 링크를 표시한다.
- Actor, Trigger, 선행 조건, 입력·유효성 검사, 처리 순서, 데이터 변화, 성공·실패·취소, 권한, 중복 실행, 최댓값·경계값, 저장·동기화, QA 기준을 원문에 따라 정리한다.
- 긴 처리 로직과 예외는 펼쳐보기로 제공할 수 있다. 기능 요약과 미구현·확인 필요 상태는 접지 않는다.
- ‘기획된 동작’과 ‘현재 구현 상태’를 구분한다. 기능 미구현을 이유로 원래 명세를 지우거나 ‘동작하지 않음’만 표시하지 않는다.
- 원문에 없는 필드는 ‘원문 미기재’로, 결정이 필요한 정책은 ‘확인 필요’로 표시한다.

5. 문서와 시연의 독립성
- 문서 본문에 ‘이 화면 시연하기’ 버튼을 만들지 않는다.
- 문서의 번호를 선택해도 시연 탭으로 이동하지 않는다.
- 시연 화면 안에 ‘관련 문서 보기’ 버튼을 만들지 않는다.
- 문서에서 선택한 구성 요소나 상태를 시연에 자동 반영하지 않는다.
- 전역 탭은 각각의 독립된 진입점이다. 전체 흐름 카드의 두 버튼은 각각 명시된 화면에 진입한다.

6. 실제 동작하는 시연하기
- 이미지 한 장에 클릭 영역을 얹는 방식이 아니라 실제 React 버튼·입력·카드·모달·상태 변화로 구현한다.
- Dev Mode 추출 자료의 레이아웃, 비율, 색상, 간격, 글꼴과 에셋을 가능한 범위에서 재현한다.
- 원문 User Flow와 화면 정의서에 따라 화면 이동, 취소, 뒤로가기, 입력 검증과 비활성 조건을 구현한다.
- 문서의 화면 ID·Feature ID와 구현을 매핑하되 사용자 화면에는 불필요한 개발 정보를 넣지 않는다.
- API나 차량·기기 연동이 없으면 Mock Data를 사용하고 데모 안내에서 실제 연동 범위를 밝힌다.
- 로그인, 결제, 차량 제어 등을 실제로 처리한 것처럼 표현하지 않는다.
- 새로고침 후 유지 여부는 명세를 따른다. 미정이면 확인 필요로 표시하고, 시연에 필요한 임시 상태의 범위를 따로 기록한다.
- 개별 화면 직접 진입에 필요한 목업 초기 상태를 제공한다. 문서에서 상태를 전달받아야만 동작하는 구조로 만들지 않는다.

7. 자료 충돌·누락 처리
- 동일 정책이 자료마다 다르면 양쪽 출처와 차이를 표시한다.
- 미정 정책을 확정하거나 존재하지 않는 ID·원본 번호를 만들어내지 않는다.
- 문서 UI의 여백·카드 배치 등 표현상의 선택은 위 지침 안에서 진행한다. 서비스 정책 변경과 구별한다.
- 화면 수와 기능 수는 실제 자료에서 계산한다. 예시 프로젝트의 개수를 복사하지 않는다.

8. 구현·검증
- 자료 분석 → 화면/기능 매핑 → 문서 구조 → 프레임 분리와 번호 연결 → 독립 데모 → 검증 → 배포 준비 순서로 진행한다.
- 매 단계마다 새로운 프롬프트를 요구하지 말고 진행 상황만 간단히 알려준다.
- 기존 화면·기능과 사용자 수정은 보존한다.
- 정상·실패·취소·빈 상태·중복 실행·경계값과 핵심 사용자 흐름을 명세에 따라 확인한다.
- 모바일·데스크톱에서 문서의 폭, 프레임 크기, 번호 위치, 확대·축소·화면 맞춤, 문서 스크롤을 확인한다.
- 새로고침과 직접 URL 진입, 문서 이전·다음, 정적 미리보기, 문서/시연 독립성을 확인한다.
- 프로젝트에서 lint와 build를 직접 실행하고 오류가 있으면 수정 후 다시 확인한다. 나에게 명령어 실행을 맡기지 않는다.
- 브라우저나 검증 환경을 사용할 수 없어 확인하지 못한 항목은 미검증으로 보고한다.

9. 파일·GitHub·배포
- README에 소개, 메뉴 구성, 개발자용 실행 방법, 자료 출처, Mock 범위, 저장 조건과 미구현 항목을 작성한다.
- 화면·기능·프레임·구성 요소의 매핑과 QA 확인 결과도 문서 파일로 남긴다.
- 비밀 키, .env, 실제 개인정보가 커밋에 포함되지 않았는지 확인한다.
- 요청한 변경을 커밋하고 지정한 원격 저장소의 작업 브랜치에 푸시한다. 강제 푸시와 무관한 변경 삭제는 하지 않는다.
- 인증·권한·네트워크 문제로 막히면 어느 단계까지 완료됐는지 구분해 보고한다. 가능한 연결/로그인 절차를 안내하되 존재하지 않는 승인 버튼이나 기능을 가정하지 않는다.
- Vercel 배포 권한이 있으면 배포 후 실제 URL에서 확인한다. 없으면 브라우저에서 수행할 단계와 프로젝트에 맞는 Framework, Root Directory, Build Command, Output Directory를 알려준다.
- 커밋 완료, 푸시 완료, 배포 완료를 각각 구분한다. 배포 URL을 추측하지 않는다.
